# Pilot Demo Survey Evaluation Summary

## Session context

- Demo: Simulated finals-week demo with seeded backend data
- Student respondents: 8
- Professor respondents: 4

## Student Likert averages (1–5)

| Question | Average | Meets ≥ 4.0 target |
| --- | ---: | --- |
| Ease of use | 4.5 | Yes |
| Anonymous vs. identified understanding | 4.5 | Yes |
| Comfort submitting anonymously | 4.5 | Yes |
| Check-in clarity | 4.0 | Yes |
| Confirmation clarity | 4.5 | Yes |
| More likely to seek help | 4.5 | Yes |

## Professor Likert averages (1–5)

| Question | Average | Meets ≥ 4.0 target |
| --- | ---: | --- |
| Request queue clarity | 4.5 | Yes |
| Clustering usefulness | 4.5 | Yes |
| Recommendation card usefulness | 4.5 | Yes |
| Professor control | 5.0 | Yes |
| Perceived workload reduction | 4.25 | Yes |

## Headline findings

- Student ease-of-use and anonymous-comfort averages both exceed the 4.0 target.
- Professors rated dashboard clarity and human-in-the-loop control at or above 4.0.
- Group review sessions were the most cited useful recommendation type.
- Grading/admin routes were the most cited recommendation type needing caution.
- Qualitative feedback emphasized privacy-preserving status lookup and professor approval before student updates.

## Qualitative themes

### Students
- Clear labels on the anonymous toggle made me feel safe asking a basic question.
- Nothing major; maybe a larger font on the question box.
- Would use this during finals week.
- Knowing the request code lets me check status without giving my name.
- Prefer clear typing of student ID over any scanner step.

### Professors
- Would want persisted office hours reflected in calendar export sooner.
- Add one-click edit before approve.
- No major privacy concerns if anonymous mode stays default.
- Need clearer signal when a cluster mixes urgent and routine requests.
- Cards are strong; maybe show total students affected.
