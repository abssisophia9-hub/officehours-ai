PROJECT OVERVIEW
Finals-week support overload and student hesitation create repeated, urgent asks across email and Canvas. OfficeHours AI is a unified multi-role campus app that triages asks, staffs TAs, and lets professors stamp Study Agent answers. Contribution: gated local-NLP triage designed for Canvas-first deployment—not an unconstrained chatbot.
• Context / application area: AUI courses; students, TAs, and professors during peak academic support demand (finals week and assignment spikes).
• Proposed idea: React SPA + FastAPI with Ask Triage, Help Coach, professor-stamped Study Agent, Rooms, and Canvas LTI/materials sync.
• Expected contribution: Course-scoped triage, dual-TA staffing, KB approval gate, and a demo→live Canvas deployment path—not an unconstrained chatbot.

PROBLEM DEFINITION & RELEVANCE
Students need a lower barrier to ask; staff need less repeat load; faculty must control AI-facing answers.
• Problem statement / research question: How can campus office hours cut repeat load and lower ask barriers while keeping professors in control of AI answers?
• Stakeholders / intended users: Students (Quiet asks, Study Agent, Strategist, Rooms); TAs (Live Queue, Help Coach); Professors (Repeated Topics, KB stamp, Canvas sync).
• Evidence, scope & constraints: Synthetic/silver FYP labels; local ML by default; live Canvas needs IT credentials + HTTPS. No portal scraping; no unconstrained LLM backend.

RELATED WORK, GAP & PROPOSED INNOVATION
Compare LMS inboxes and discussion forums to a gated triage product with dual-TA staffing.
• Existing work / alternatives: LMS inboxes; Piazza/Ed-style forums; tutoring chatbots; FAQ bots without professor gates or dual-TA matching.
• Gap / unmet need: Missing Quiet escalation + local triage ML + dual-TA staffing + professor stamp before student-facing AI.
• Proposed innovation: Ask Triage + Help Coach + stamped Study Agent in one multi-role app; Canvas LTI; trackable Quiet asks.

PROPOSED SYSTEM / RESEARCH DESIGN
Architecture: clients call FastAPI; Ask Triage/Help Coach/Study Agent; SQL DB; Canvas LTI + REST.
• Software: Unified React SPA; FastAPI (requests/ta/knowledge/lti); SQLite→Postgres; WebSocket hub; Quiet-ask privacy; role-scoped UI.
• Agents/models: Ask Triage = MiniLM embeddings + LogisticRegression + RAG (joblibs); Help Coach = TA assist; Study Agent = approved KB only; Strategist = client gap planner until live grades.

METHODOLOGY / PROPOSED TECHNICAL APPROACH
Local NLP triage + professor gate fits campus integrity better than unconstrained LLM tutoring.
• Proposed methodology: Iterative prototyping with CI builds (backend + officehours-app) and role walkthrough demos.
• Technologies / methods: FastAPI, React/Vite/Tailwind, SQLAlchemy, sentence-transformers (MiniLM), scikit-learn, WebSockets, Canvas LTI 1.3 + REST.
• Data / resources: Synthetic/silver ask labels; gold-label TA lab; demo Canvas mirror; live course modules when IT enables.
• Reproducibility / management: GitHub CI; docs/ (architecture, NLP, ops); train scripts; reports/; OFFICEHOURS_DEMO toggle.

Feasible as staged demo→live; main risk is campus credential latency.
• Required resources: Dev laptop; GitHub; SQLite→Postgres host; Canvas LTI key/token; optional Entra; no GPU required for MiniLM demo.

ETHICS, PRIVACY, SECURITY & RESPONSIBLE AI
Privacy, security, and responsible AI are in scope for a campus help product.
• Privacy / human participants: Quiet asks; course-scoped data; minimize PII in logs; role auth; retention aligned with course term.
• Cybersecurity / legal / standards: Auth + CORS; HTTPS for live; no portal scraping; Canvas LTI 1.3; least-privilege API tokens.
• AI use plan: Local Ask Triage + Help Coach; Study Agent quotes only professor-stamped KB; external LLM off by default; refuse weak/missing KB.
• AI system risks if applicable: Label bias; triage miss → human TA path; hallucination mitigated by stamp gate; misuse limited by course auth.
